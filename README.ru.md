[![npm license](https://img.shields.io/npm/l/dsh-locale-ru.svg)](LICENSE)
[![CI](https://github.com/vowa-antilamer/dsh-locale-ru/actions/workflows/ci.yml/badge.svg)](https://github.com/vowa-antilamer/dsh-locale-ru/actions/workflows/ci.yml)

Русификация веб-интерфейса [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness).
Это языковой пакет для штатного сервиса `@deepseek-ai/dsh-client-locale`: он добавляет язык
**Русский** и регистрирует словари для **60 пространств имён / 3843 строк** — чат и composer,
диалог и траектория, все боковые панели, все страницы настроек, плагины и Cordis, цели и планы,
субагенты, вопросы и подтверждения, а также сторонние плагины `dsh-market`, `better-sidebar`,
`dsh-pet` и `dsh-mcp`.

[English documentation](README.md)

## Возможности

- Регистрирует `ru` с откатом на английский: ключ без перевода разрешается в `en` (затем в общее
  пространство `common`), поэтому неполный словарь никогда не ломает интерфейс.
- Выбирает русский **один раз** — при первой загрузке после установки (флаг в `localStorage`
  дальше отдаёт выбор вам); возврат на английский в настройках больше не переопределяется.
- Покрывает сторонние плагины: их словари лежат в `src/locales/plugins/`, по файлу на пространство
  имён, и регистрируются на один такт позже загрузки страницы. Поэтому плагин, который сам
  поставляет `ru`, остаётся владельцем своего пространства имён, а не проигрывает гонку пакету.
- Никаких зависимостей: host-половина пустая, клиентский модуль самодостаточен, поэтому пакет
  ставится в профиль, не трогая граф зависимостей.
- Сгенерированный артефакт и тесты, которые следят за полнотой и согласованностью словаря — включая
  сверку каждого словаря плагина с установленной рядом копией плагина.

## Установка

### В профиль DSH

Откройте **Настройки → Плагины → Установить**, введите `dsh-locale-ru` и подтвердите. Менеджер
плагинов добавит пакет и строку в набор профиля; язык сразу появится в
**Настройки → Общие → Язык**.

Из локальной копии репозитория устанавливайте каталог:

```bash
dsh plugin --profile web add /path/to/dsh-locale-ru
```

затем добавьте `"dsh-locale-ru"` в список `dsh.profile.bundles` в `package.json` профиля
(мастер установки в интерфейсе делает оба шага сам).

### Переключение языка

**Настройки → Общие → Язык → Русский.** Выбор хранится в пользовательских настройках хоста и
переживает перезапуск. «English» возвращает английский.

## Перевод стороннего плагина

Клиентский плагин либо переводит текст через сервис локализации (`ctx.locale.register(...)`), либо,
что бывает редко, собственным словарём. Пакет покрывает первый случай:

- `src/locales/plugins/<пространство>.json` — по одному словарю на пространство имён плагина, в том
  же формате `{ "<ключ>": { "en": "…", "ru": "…" } }`, что и файлы ядра. Достаточно положить файл:
  пространство имён появляется в интерфейсе только вместе с плагином, который его регистрирует,
  поэтому неиспользуемый словарь ничего не стоит.
- Пространства имён плагинов регистрируются на один такт позже загрузки страницы. Сервис
  локализации отвергает вторую регистрацию той же пары «пространство имён + язык», поэтому ранний
  захват заставил бы собственный словарь плагина упасть; поздняя регистрация отдаёт приоритет
  плагину, а пакет дополняет только те плагины, где русского нет вовсе.
- Сборка падает, если одно пространство имён объявлено и как словарь ядра, и как словарь плагина:
  такая пара зарегистрировалась бы дважды.

Чтобы добавить плагин:

```bash
# 1. установите плагин в профиль и сравните пакет с живой установкой
node scripts/extract-dictionaries.mjs <dsh>/node_modules/@deepseek-ai "$DSH_PROFILE_DIR/node_modules" --drafts
# 2. заполните "ru" в .plugin-drafts/<пространство>.json и перенесите файл в src/locales/plugins/
npm run verify
```

Утилита печатает все найденные пространства имён, помечает плагинные тегом `[plugin]` и пишет
черновики переводов для всего, где русского ещё нет (`--drafts`, каталог в `.gitignore`). Без
аргумента профиля она сравнивает только бандлы ядра; `<dsh>` — каталог установки dsh (для установки
через `npx` это `~/.npm/_npx/<hash>`).

## Разработка

В репозитории английский исходник лежит рядом с переводом, поэтому полноту можно проверять:

```
src/locales/<пространство>.json          { "<ключ>": { "en": "…", "ru": "…" } } — пространства имён ядра
src/locales/plugins/<пространство>.json  тот же формат для сторонних плагинов
scripts/build.mjs                        собирает lib/client.js из обоих каталогов
scripts/extract-dictionaries.mjs         утилита: сравнить установленный DSH/профиль, написать черновики
test/locale.test.mjs                     тесты клиентского модуля на node:test
test/plugins.test.mjs                    разделение ядра и плагинов, защита от дрейфа
lib/client.js                            сгенерированный клиентский модуль (в git и в npm-пакете)
```

```bash
npm run build     # пересобрать lib/client.js
npm run check     # упасть, если lib/client.js устарел (проверка для CI)
npm test          # структура модуля, регистрация языка, совпадение ключей и плейсхолдеров
npm run verify    # check + test
```

### Обновление словаря после обновления DSH

```bash
node scripts/extract-dictionaries.mjs /path/to/dsh/node_modules/@deepseek-ai "$DSH_PROFILE_DIR/node_modules"
```

Каждое найденное в установленных бандлах пространство имён сравнивается с `src/locales` и
`src/locales/plugins`: `MISSING` и `REMOVED` показывают дрейф ключей, `NEW` — непереведённое
пространство имён, `UNUSED` — словарь, который больше никто не регистрирует, а `OWN-RU`
предупреждает, что плагин переводит себя сам, и файл пакета для него нужно удалить. Переведите
новые строки, удалите исчезнувшие и запустите `npm run verify`.

## Ограничения

- Текст, который не проходит через сервис локализации, остаётся непереведённым: служебные сообщения
  хоста вне интерфейса (например, простой текст `dsh web authentication required`) и плагины,
  которые рисуют текст своим словарём вместо регистрации в сервисе — у `@linxin666/dsh-pet` страница
  настроек становится русской, но плавающий питомец и его игровой HUD берут текст из собственного
  словаря `zh`/`en` по `document.documentElement.lang`, поэтому остаются китайскими, пока плагин не
  начнёт переводить себя через сервис локализации.
- Плагин, для которого здесь нет словаря (например, `dsh-hud`), остаётся английским: запустите
  утилиту выше, чтобы увидеть, чего не хватает.
- В сервисе локализации нет правил множественного числа, поэтому строки со счётчиками используют
  формы, не зависящие от числа (`Файлов: {count}`).
- Пространства имён, которые монтируются только в Desktop-рендерере (`settings.account`),
  намеренно не переведены: веб-профиль их не загружает.
